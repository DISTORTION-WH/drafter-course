# Глава 3. Установка редактора, Node.js и Git

## 1. Что устанавливаем

Нужны три отдельные программы:

1. VS Code — редактор исходного кода.
2. Node.js LTS — среда выполнения JavaScript вне браузера.
3. Git — система контроля версий.

Установка VS Code не устанавливает Node.js. Установка Node.js не устанавливает Git. Каждую программу проверяем отдельно.

## 2. Безопасность установки

Скачивайте установщики только с официальных сайтов:

- [VS Code for Windows](https://code.visualstudio.com/docs/setup/windows)
- [Node.js download](https://nodejs.org/en/download)
- [Git for Windows](https://git-scm.com/install/windows)

Не скачивайте «сборки для программистов» с файловых каталогов, форумов или случайных ссылок.

## 3. Установка VS Code

Официальная документация рекомендует Windows User Setup для большинства пользователей. Она не требует установки для всех пользователей компьютера и поддерживает обычное фоновое обновление.

Порядок:

1. Откройте официальную страницу.
2. Скачайте Windows User Installer подходящей архитектуры, обычно x64.
3. Запустите установщик.
4. Разрешите добавление команды `code` в `PATH`, если установщик предлагает эту опцию.
5. Завершите установку.
6. Полностью закройте старые окна PowerShell.
7. Откройте новый PowerShell.

Проверка:

```powershell
code --version
```

Открытие текущей папки:

```powershell
code .
```

Точка означает текущую папку.

## 4. Что такое `PATH`

`PATH` — список папок, в которых терминал ищет исполняемую программу по короткому имени.

Когда вы вводите:

```powershell
code
```

PowerShell ищет `code` в папках из `PATH`.

После установки программа может быть уже добавлена в `PATH`, но ранее открытый терминал ещё использует старое окружение. Поэтому сначала перезапустите терминал и только потом диагностируйте проблему.

Не редактируйте системный `PATH` вручную без необходимости.

## 5. Интерфейс VS Code

Основные области:

- Explorer — файлы проекта;
- Editor — содержимое файла;
- Terminal — встроенный PowerShell;
- Problems — ошибки анализаторов;
- Source Control — Git;
- Extensions — дополнения;
- Run and Debug — отладчик.

Полезные сочетания:

```text
Ctrl+Shift+P  Command Palette
Ctrl+P        быстрый поиск файла
Ctrl+`        показать/скрыть терминал
Ctrl+S        сохранить файл
Ctrl+Shift+F  поиск по проекту
F2            переименование символа
F5            запуск отладчика
```

## 6. Минимальные extensions

Пока достаточно:

- ESLint;
- Prettier — Code formatter.

Не устанавливайте десятки расширений сразу. Каждое расширение — дополнительный код, настройки, обновления и потенциальные конфликты.

JavaScript, TypeScript, Node.js debugging и Git уже поддерживаются VS Code без отдельного extension.

## 7. Установка Node.js

На 16 июля 2026 официальный сайт предлагает Node.js 24 LTS как рекомендуемую LTS-линию. Но правило курса долговечнее конкретного номера: выбирайте актуальную LTS-версию, а не Current или EOL.

Порядок:

1. Откройте официальную страницу Node.js.
2. Выберите LTS.
3. Скачайте Windows Installer `.msi`.
4. Запустите установщик.
5. Оставьте стандартную установку npm и добавление в `PATH`.
6. Завершите установку.
7. Закройте все старые терминалы.
8. Откройте новый PowerShell.

Проверка:

```powershell
node --version
npm --version
```

Ожидается вывод версий, например:

```text
v24.x.x
11.x.x
```

Точные patch-версии могут отличаться.

## 8. Node.js и npm — разные вещи

Node.js выполняет JavaScript:

```powershell
node .\src\index.js
```

npm управляет проектом и пакетами:

```powershell
npm install
npm test
```

npm обычно устанавливается вместе с Node.js.

## 9. Проверка Node.js

Создайте `hello.js`:

```js
const message = "Node.js работает";
console.log(message);
```

В терминале перейдите в папку файла и выполните:

```powershell
node .\hello.js
```

Ожидаемый вывод:

```text
Node.js работает
```

## 10. Установка Git

Скачайте поддерживаемый Git for Windows с официальной страницы. Для первого курса допустимы стандартные настройки установщика.

Важные пункты:

- Git должен быть доступен из PowerShell;
- VS Code можно оставить редактором для работы с кодом;
- line endings можно оставить на рекомендуемом установщиком Windows-варианте;
- не требуется менять системную shell на Git Bash — курс использует PowerShell.

Проверка:

```powershell
git --version
```

Git подробно изучается в отдельной части. Сейчас важно только подтвердить установку.

## 11. Диагностика «команда не найдена»

Если `node`, `npm`, `git` или `code` не распознаны:

1. Закройте терминал.
2. Откройте новый.
3. Повторите проверку.
4. Убедитесь, что установка завершилась успешно.
5. Найдите программу через меню Пуск.
6. Проверьте официальную инструкцию программы.
7. Только затем рассматривайте переустановку.

Не скачивайте случайный `node.exe` и не копируйте его вручную в системные папки.

## 12. Проверочный лист

В новом PowerShell выполните:

```powershell
code --version
node --version
npm --version
git --version
```

Сохраните вывод в журнал обучения. Точные версии понадобятся при разборе проблем.

## Definition of Done

- `code --version` работает.
- `node --version` работает.
- `npm --version` работает.
- `git --version` работает.
- Вы запускаете `.js`-файл через Node.js.
- Вы понимаете назначение `PATH` на базовом уровне.
- Вы не путаете runtime, editor и package manager.
