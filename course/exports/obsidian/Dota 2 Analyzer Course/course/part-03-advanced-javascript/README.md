## Цель

Научиться строить преобразования коллекций и понимать код, который ожидает файл, сеть или таймер.

Итоговый проект читает историю матчей из JSON-файла и рассчитывает:

- количество матчей;
- победы Radiant и Dire;
- среднюю длительность;
- суммарные kills;
- число уникальных игроков;
- частоту выбора героев;
- статистику побед и kills по героям;
- наиболее популярного героя;
- краткие сведения о каждом матче.

## Основной переход этой части

Раньше данные находились прямо в JavaScript:

```js
const match = { /* ... */ };
```

Теперь:

```text
JSON-файл
→ асинхронное чтение
→ JSON.parse
→ validation
→ immutable transformations
→ aggregates
→ console report
```

Такой pipeline уже похож на будущий сбор данных из внешнего API. Позднее вместо `readFile` появится HTTP request, но Promise, validation и domain-аналитика останутся.

## Как проходить

Читайте главы по порядку. После главы 6 не переходите сразу к эталону: сначала выполните лабораторную из главы 10 самостоятельно. Эталонный проект нужен для сравнения и отладки, а не для бездумного копирования.

Ориентировочный темп для новичка — 2–4 недели по 60–90 минут в день. Скорость не является критерием; критерий — способность объяснить код и повторить решение без подсказки.
