# Эталонное решение лабораторной

Сначала выполните лабораторную самостоятельно. Эталон нужен для сравнения решений, а не для замены попытки.

Полный исполняемый пример находится в файле [examples/match-analyzer.js](examples/match-analyzer.js).

## 1. Как сравнивать

Не проверяйте только совпадение строк. Ответьте:

1. Совпадают ли контракты функций?
2. Проверяете ли вы данные до чтения свойств?
3. Изменяется ли исходный объект?
4. Что происходит при пустом массиве?
5. Где выполняется округление?
6. Разделены ли расчёт и вывод?
7. Сообщает ли ошибка, какое поле неверно?

Ваше решение может отличаться и оставаться правильным.

## 2. Порядок функций

Эталон разделён на уровни:

```text
простые predicates
  isNonEmptyString
  isNonNegativeNumber

простые расчёты
  roundToTwoDigits
  calculateKda
  formatDuration

валидация
  validatePlayer
  validateMatch

преобразование
  analyzePlayer
  createTeamSummary
  findTopPlayer
  createMatchReport

представление
  printMatchReport
```

Функции нижнего уровня не знают о консоли или полном матче. Благодаря этому их легко повторно использовать и тестировать.

## 3. Почему исходный игрок не изменяется

```js
return {
  ...player,
  kda: roundToTwoDigits(
    calculateKda(player.kills, player.deaths, player.assists),
  ),
};
```

Spread копирует свойства в новый объект. Поле `kda` добавляется в копию.

Проверка:

```js
const analyzed = analyzePlayer(match.players[0]);

console.log(analyzed.kda);       // число
console.log(match.players[0].kda); // undefined
```

## 4. Почему валидация возвращает массив

Возврат массива позволяет получить полный отчёт за один проход:

```text
players[3]: hero должен быть непустой строкой;
players[7]: kills должен быть неотрицательным числом
```

Для массового импорта Dota 2 данных это полезнее, чем останавливаться после первого неверного поля.

## 5. Почему `analyzePlayer` выбрасывает ошибку

Контракт `analyzePlayer` обещает вернуть корректно проанализированного игрока. Если вход невалиден, функция не может выполнить обещание.

Она не должна молча возвращать частичный объект:

```js
if (errors.length > 0) {
  throw new Error(`Невалидный игрок: ${errors.join(", ")}`);
}
```

## 6. Почему `findTopPlayer` возвращает `null`

У пустого массива нет лучшего игрока. `null` здесь сознательно обозначает отсутствие результата.

Вызывающий код обязан учесть это:

```js
if (report.topPlayer !== null) {
  console.log(report.topPlayer.name);
}
```

В TypeScript будущий тип будет выглядеть примерно так:

```ts
Player | null
```

Компилятор заставит проверить `null`.

## 7. Почему округление выполняется поздно

Многократное округление промежуточных значений накапливает погрешность. Общее правило:

- внутри расчётов хранить максимально точное значение;
- округлять при создании публичной метрики или отображении.

В первой учебной версии KDA игрока округляется при анализе, поэтому среднее строится из уже округлённых значений. В production-аналитике лучше хранить сырое значение или numerator/denominator и округлять финальный aggregate.

Это хороший пример того, как учебное упрощение позже уточняется.

```text
Матч: 8123456789
Длительность: 41:10
```

Если вывод отличается, проверьте исходные данные и функции по отдельности.
