# Глава 2. Окружения и доступ к локальному API

## 1. Зачем нужны разные окружения

У приложения минимум три окружения:

| Окружение | Назначение | Пример API |
|---|---|---|
| local/development | работа на вашем компьютере | `http://192.168.1.50:3000` |
| staging | проверка почти production-сборки | `https://api-staging.example.com` |
| production | реальные пользователи | `https://api.example.com` |

У каждого окружения должны быть отдельные база, Redis, очереди, push-учётные данные и допустимые redirect URL. Тестовый пользователь не должен случайно подписаться на production-уведомления.

## 2. Публичная переменная Expo

В Expo адрес API можно читать из переменной с префиксом `EXPO_PUBLIC_`:

```env
EXPO_PUBLIC_API_BASE_URL=http://192.168.1.50:3000
```

Файл с локальным значением обычно называется `.env.local` и не попадает в Git. В коде используется статическая запись:

```ts
const rawApiBaseUrl = process.env.EXPO_PUBLIC_API_BASE_URL;
```

Не используйте динамический доступ `process.env[name]`: Expo подставляет публичные значения при сборке для статического обращения. И не храните здесь секреты. Всё с префиксом `EXPO_PUBLIC_` можно извлечь из установленного приложения.

Адрес API не секрет. Ключ Steam Web API — секрет и существует только на backend.

## 3. Валидируем конфигурацию при запуске

Создайте `src/config/env.ts`:

```ts
function requirePublicUrl(name: string, value: string | undefined): string {
  if (!value) {
    throw new Error(`Не задана переменная ${name}`);
  }

  const url = new URL(value);

  if (!['http:', 'https:'].includes(url.protocol)) {
    throw new Error(`${name} должна быть HTTP(S)-ссылкой`);
  }

  return url.toString().replace(/\/$/, '');
}

export const env = {
  apiBaseUrl: requirePublicUrl(
    'EXPO_PUBLIC_API_BASE_URL',
    process.env.EXPO_PUBLIC_API_BASE_URL,
  ),
};
```

Разберём функции:

- `name: string` — имя переменной для сообщения;
- `value: string | undefined` — значение может отсутствовать;
- `: string` после скобок — функция обязана вернуть строку;
- `new URL(value)` проверяет синтаксис;
- `replace(/\/$/, '')` убирает один завершающий `/`, чтобы не получить `//v1/matches`;
- `env` — единственный объект, из которого остальные модули читают конфигурацию.

Для production добавьте проверку HTTPS на уровне профиля сборки или runtime-конфигурации. Обычный HTTP допустим только для осознанной локальной разработки.

## 4. Почему `localhost` не работает на телефоне

`http://localhost:3000` означает «порт 3000 на том устройстве, где выполняется приложение».

- Expo Web на компьютере: это ваш компьютер.
- iOS Simulator: правила зависят от сетевой конфигурации, часто хост доступен через localhost.
- Android Emulator: хост-машина обычно доступна через специальный адрес эмулятора, часто `10.0.2.2`.
- Физический телефон: нужен LAN-IP компьютера, например `192.168.1.50`.

Для физического устройства:

1. Телефон и компьютер находятся в одной доверенной Wi-Fi-сети.
2. NestJS слушает не только loopback, если вы сознательно разрешаете доступ из LAN.
3. Firewall разрешает нужный входящий порт только для подходящей сети.
4. В `.env.local` указан LAN-IP компьютера.
5. На телефоне в браузере открывается безопасный тестовый endpoint, например `/health`.

Не открывайте локальную базу или Redis наружу. Телефону нужен только HTTP-порт backend.

## 5. Конфигурация staging и production

Для EAS Build значения задаются окружениями/профилями сборки. Не переключайте окружение с помощью `NODE_ENV`: экосистема использует его для собственных режимов, и такое переключение легко даёт неожиданный результат.

Практическая политика:

```text
development build -> development API
preview build     -> staging API
production build  -> production API
```

Отображайте имя непроизводственного окружения в настройках или маленьком debug-баннере. В production такого баннера нет.

## 6. CORS, TLS и mobile

Нативный `fetch` не подчиняется браузерному CORS так же, как web-приложение, но backend всё равно должен иметь строгую CORS-политику для web-клиента и документации. CORS не является системой авторизации.

В production:

- только HTTPS;
- валидный сертификат;
- никаких обходов проверки TLS в приложении;
- reverse proxy ограничивает размер тела и таймауты;
- health endpoint не раскрывает конфигурацию и секреты.

## 7. Проверка

Создайте локальную переменную, запустите backend и development build. Выведите только безопасный `apiBaseUrl`, но никогда не весь `process.env`. Затем откройте health endpoint с физического устройства.

Критерии готовности:

- приложение падает с понятной ошибкой, если URL не задан;
- на телефоне не используется `localhost`;
- production URL имеет HTTPS;
- в репозитории нет `.env.local` и секретов;
- адрес API выбирается профилем сборки, а не ручной правкой исходника.
