## Как объясняется код

Рассмотрим строку, которая действительно будет в API:

```ts
const match = await this.matchesService.findById(matchId);
```

Разбор всегда будет предметным:

- `const` означает, что переменной `match` нельзя позднее присвоить другой объект;
- `match` хранит найденный профессиональный матч;
- `this.matchesService` — экземпляр сервиса с бизнес-логикой матчей;
- `findById` — функция сервиса, получающая один матч по идентификатору;
- `matchId` — идентификатор из URL запроса;
- `await` останавливает только текущую async-функцию до ответа базы, а не весь сервер;
- результат нужен следующей строке controller, поэтому переменная остаётся в финальном проекте.

Не будет упражнений, где `const name = 'Alex'` существует только ради демонстрации `const`.

## Как выглядит аналогичная задача

После готового кода матча инструкция будет конкретной:

```text
Создайте apps/api/src/teams/teams.controller.ts.
Создайте класс TeamsController.
В constructor создайте параметр private readonly teamsService: TeamsService.
Создайте async-функцию findById(teamId: string).
Она вызывает teamsService.findById(teamId) и возвращает TeamDetailsResponse.
Если команда не найдена, TeamsService выбрасывает NotFoundException.
```

После задания будет эталон, но сначала вы делаете попытку сами. Смысл не в угадывании синтаксиса: вы повторяете уже разобранную конструкцию на другой реальной сущности проекта.

## Правило прохождения

Главу можно отметить завершённой только когда одновременно выполнено:

- код находится в основном репозитории;
- команда проверки завершилась успешно;
- вы открыли приложение или endpoint и увидели результат;
- вы можете своими словами объяснить каждую созданную функцию;
- изменения сохранены отдельным Git commit;
- в файле нет кода, назначение которого вам неизвестно.

## Если код не работает

Не вставляйте следующие десять фрагментов. Запишите четыре факта:

```text
Команда:
Полный текст ошибки:
Какой результат ожидался:
Последний изменённый файл:
```

Затем ищите первую строку stack trace, относящуюся к вашему файлу. Исправление считается понятным, если вы можете объяснить причину, а не только сказать «помогло».

## Использование AI

AI разрешён как наставник и reviewer. Для каждого предложенного изменения требуйте:

```text
1. назвать файл;
2. показать минимальный diff;
3. объяснить новые переменные и функции;
4. назвать команду проверки;
5. не добавлять новую библиотеку без объяснения.
```

Не принимайте сгенерированный файл, если не можете разобрать его по строкам.
