## Глава 1. Файлы, папки, расширения и пути

### 1. Файл

Файл — именованный набор данных на диске.

Примеры:

```text
match-analyzer.js
package.json
README.md
match-data.json
```

У файла есть:

- имя;
- расширение;
- содержимое;
- расположение;
- размер;
- права доступа;
- время изменения.

### 2. Расширение

Расширение — часть имени после последней точки.

```text
match-analyzer.js  → JavaScript
package.json       → JSON
README.md          → Markdown
.gitignore         → специальный файл без обычного расширения
```

Windows может скрывать расширения. Для разработки лучше включить их отображение в Проводнике: `Вид → Показать → Расширения имён файлов`.

Иначе можно случайно создать `index.js.txt`, который выглядит как `index.js`, но Node.js не воспринимает его как ожидаемый JavaScript-файл.

### 3. Папка

Папка группирует файлы и другие папки.

```text
dota-match-cli/
  src/
    index.js
  test/
    calculations.test.js
  package.json
```

Папка `dota-match-cli` здесь является корнем проекта. Корень проекта — верхняя папка, содержащая конфигурацию и исходный код конкретного приложения.

### 4. Дерево проекта

Структуру удобно читать как дерево:

```text
dota-match-cli
├── package.json
├── src
│   ├── index.js
│   ├── data
│   │   └── match.js
│   ├── domain
│   │   ├── calculations.js
│   │   ├── validation.js
│   │   └── match-report.js
│   └── presentation
│       └── print-report.js
└── test
    ├── calculations.test.js
    └── match-report.test.js
```

Отступ означает вложенность. `calculations.js` находится внутри `domain`, которая находится внутри `src`.

### 5. Путь

Путь описывает расположение файла.

Пример Windows:

```text
C:\Projects\dota-match-cli\src\index.js
```

Части:

- `C:` — диск;
- `Projects` — папка на диске;
- `dota-match-cli` — корень проекта;
- `src` — папка исходного кода;
- `index.js` — файл.

### 6. Абсолютный путь

Абсолютный путь начинается от корня файловой системы или диска:

```text
C:\Projects\dota-match-cli\src\index.js
```

Он не зависит от текущей папки терминала.

### 7. Относительный путь

Относительный путь считается от текущей рабочей папки.

Если терминал находится здесь:

```text
C:\Projects\dota-match-cli
```

то относительный путь к `index.js`:

```text
.\src\index.js
```

`.` означает текущую папку.

`..` означает родительскую папку:

```text
..\another-project
```

### 8. Текущая рабочая папка

Каждая команда терминала выполняется относительно current working directory — текущей рабочей папки.

Если вы запустили:

```powershell
node .\src\index.js
```

Node ищет `src\index.js` внутри текущей папки.

Большая часть ошибок «файл не найден» возникает не из-за отсутствия файла, а из-за неправильной текущей папки.

### 9. Пробелы в пути

Путь с пробелами заключайте в кавычки:

```powershell
Set-Location "C:\My Projects\dota-match-cli"
```

Без кавычек PowerShell может воспринять части пути как отдельные аргументы.

Для учебных проектов удобнее короткие имена без пробелов:

```text
dota-match-cli
dota-analytics
```

### 10. Разделители Windows и JavaScript imports

В PowerShell Windows часто используется обратный слеш:

```text
.\src\index.js
```

В JavaScript import обычно пишется через обычный слеш:

```js
import { calculateKda } from "./domain/calculations.js";
```

Не смешивайте синтаксис пути терминала и module specifier JavaScript.

### 11. Кодировка UTF-8

Файлы курса содержат русский текст. Сохраняйте исходники в UTF-8.

VS Code обычно использует UTF-8 по умолчанию. Текущая кодировка отображается в нижней панели редактора.

При неправильной кодировке вместо текста могут появиться нечитаемые символы.

### 12. Концы строк

Windows традиционно использует `CRLF`, Linux — `LF`. Современные инструменты умеют работать с обоими вариантами.

Важно не вручную переключать окончания строк без причины. Позже Git и formatter будут поддерживать единообразие проекта.

### 13. Скрытые и конфигурационные файлы

Примеры:

```text
.gitignore
.env
.editorconfig
```

Точка в начале имени на Unix-подобных системах означает скрытый файл. На Windows поведение отображения зависит от программы.

`.env` может содержать секреты и не должен попадать в публичный repository.

### 14. Имена файлов

Для JavaScript-проекта используйте понятные имена:

```text
calculations.js
match-report.js
print-report.js
```

Не используйте:

```text
file1.js
new.js
final-final-2.js
helpers-everything.js
```

Имя описывает ответственность файла.

### 15. Упражнения

#### Упражнение 1

Нарисуйте дерево папок для проекта, в котором есть:

- `package.json`;
- `src/index.js`;
- `src/data/match.js`;
- `src/domain/calculations.js`;
- `test/calculations.test.js`.

#### Упражнение 2

Если текущая папка `C:\Projects\dota-match-cli`, напишите относительный путь к `test\calculations.test.js`.

#### Упражнение 3

Объясните разницу:

```text
C:\Projects\dota-match-cli\src\index.js
.\src\index.js
```

#### Упражнение 4

Объясните, почему файл `index.js.txt` является проблемой.

### Definition of Done

- Вы отличаете файл, папку и расширение.
- Вы понимаете корень проекта.
- Вы различаете абсолютный и относительный путь.
- Вы знаете значения `.` и `..`.
- Вы понимаете роль текущей рабочей папки.
- Вы умеете читать дерево проекта.

## Глава 2. PowerShell и командная строка

### 1. Что такое терминал

Терминал — текстовый интерфейс для запуска программ и управления файлами.

PowerShell — оболочка Windows, которая читает введённые команды, выполняет их и показывает результат.

Пример приглашения:

```text
PS C:\Projects\dota-match-cli>
```

Часть до `>` показывает текущую папку. Текст после `>` вводите вы.

### 2. Как открыть PowerShell

Варианты:

- открыть Windows Terminal и выбрать PowerShell;
- открыть PowerShell через меню Пуск;
- в VS Code выбрать `Terminal → New Terminal`.

В курсе предпочтителен встроенный терминал VS Code: редактор и команда работают с одной папкой проекта.

### 3. Команда, аргумент и параметр

```powershell
Get-ChildItem -Force .\src
```

Здесь:

- `Get-ChildItem` — команда;
- `-Force` — именованный параметр;
- `.\src` — аргумент-путь.

PowerShell-команды часто называются `Глагол-Существительное`:

```text
Get-Location
Set-Location
Get-ChildItem
New-Item
Get-Content
```

### 4. Узнать текущую папку

```powershell
Get-Location
```

Короткий знакомый аналог:

```powershell
pwd
```

В курсе показываются полные имена PowerShell-команд, потому что они лучше объясняют действие.

### 5. Показать содержимое папки

```powershell
Get-ChildItem
```

Показать также скрытые элементы:

```powershell
Get-ChildItem -Force
```

Показать конкретную папку:

```powershell
Get-ChildItem .\src
```

### 6. Перейти в папку

```powershell
Set-Location C:\Projects
```

Относительный переход:

```powershell
Set-Location .\dota-match-cli
```

Вернуться на уровень выше:

```powershell
Set-Location ..
```

После перехода всегда можно проверить:

```powershell
Get-Location
Get-ChildItem
```

### 7. Автодополнение

Введите часть имени и нажмите `Tab`:

```text
Set-Location .\dota-m<Tab>
```

PowerShell дополнит существующий путь. Это быстрее и уменьшает количество опечаток.

### 8. Создать папку

```powershell
New-Item -ItemType Directory -Path .\dota-match-cli
```

Перейти в неё:

```powershell
Set-Location .\dota-match-cli
```

Создать вложенные папки по очереди:

```powershell
New-Item -ItemType Directory -Path .\src
New-Item -ItemType Directory -Path .\test
```

### 9. Создать пустой файл

```powershell
New-Item -ItemType File -Path .\src\index.js
```

Обычно содержимое исходников удобнее писать в VS Code, а не командами терминала.

### 10. Прочитать текстовый файл

```powershell
Get-Content .\src\index.js
```

Прочитать целиком как одну строку:

```powershell
Get-Content -Raw .\package.json
```

### 11. Копирование и перемещение

```powershell
Copy-Item .\src\index.js .\src\index-backup.js
```

```powershell
Move-Item .\src\index-backup.js .\src\old-index.js
```

Перед операцией проверьте существование источника и папку назначения.

### 12. Удаление: правило осторожности

Удаление через терминал может не использовать Корзину. На начальном этапе удаляйте файлы через Проводник или Explorer VS Code.

Не копируйте неизвестные команды с `Remove-Item`, особенно с `-Recurse`, `-Force`, wildcard `*` или вычисляемым путём.

Перед любой потенциально разрушительной командой:

1. Выполните `Get-Location`.
2. Выведите целевой путь.
3. Убедитесь, что это папка проекта.
4. Проверьте содержимое через `Get-ChildItem`.
5. Только затем решайте, нужна ли операция.

### 13. Остановить программу

Если программа долго работает или запущен сервер:

```text
Ctrl+C
```

Это отправляет процессу сигнал остановки.

Если вы случайно создали бесконечный цикл, `Ctrl+C` — первое действие.

### 14. Очистить экран

```powershell
Clear-Host
```

Это не удаляет файлы и не стирает историю команд, а только очищает видимую область терминала.

### 15. История команд

Клавиши ↑ и ↓ показывают ранее введённые команды. Не набирайте длинную команду заново, если нужно изменить один аргумент.

### 16. Кавычки

Для путей с пробелами:

```powershell
Set-Location "C:\My Projects\dota-match-cli"
```

Одинарные кавычки в PowerShell обычно не подставляют переменные, двойные могут подставлять. До изучения переменных shell используйте кавычки только для явных путей и не составляйте разрушительные команды из строк.

### 17. Результат команды и код завершения

Команда может:

- завершиться успешно;
- вернуть понятную ошибку;
- запустить долгоживущий процесс;
- ожидать ввода.

Читайте весь вывод. Красный текст не всегда означает повреждение системы: чаще это описание неверного пути, неизвестной команды или отсутствующего файла.

### 18. Частые ошибки

#### Неправильная папка

```text
Cannot find path ... because it does not exist
```

Проверьте `Get-Location` и `Get-ChildItem`.

#### Пропущены кавычки

Путь с пробелами разделился на аргументы.

#### Опечатка в имени

Используйте `Tab` для дополнения.

#### Команда не найдена

```text
The term 'node' is not recognized...
```

Программа не установлена или её папка отсутствует в `PATH`. Это будет разобрано в следующей главе.

### 19. Лабораторное упражнение

В безопасной учебной папке создайте структуру:

Порядок:

3. Создайте `dota-tools-practice`.
4. Перейдите внутрь.

7. Выведите дерево через несколько `Get-ChildItem`.
8. Откройте папку в VS Code после установки редактора.

## Глава 3. Установка редактора, Node.js и Git

### 1. Что устанавливаем

Нужны три отдельные программы:

1. VS Code — редактор исходного кода.
2. Node.js LTS — среда выполнения JavaScript вне браузера.
3. Git — система контроля версий.

Установка VS Code не устанавливает Node.js. Установка Node.js не устанавливает Git. Каждую программу проверяем отдельно.

### 2. Безопасность установки

Скачивайте установщики только с официальных сайтов:

- [VS Code for Windows](https://code.visualstudio.com/docs/setup/windows)
- [Node.js download](https://nodejs.org/en/download)
- [Git for Windows](https://git-scm.com/install/windows)

Не скачивайте «сборки для программистов» с файловых каталогов, форумов или случайных ссылок.

### 3. Установка VS Code

Официальная документация рекомендует Windows User Setup для большинства пользователей. Она не требует установки для всех пользователей компьютера и поддерживает обычное фоновое обновление.

Порядок:

1. Откройте официальную страницу.
2. Скачайте Windows User Installer подходящей архитектуры, обычно x64.
3. Запустите установщик.
4. Разрешите добавление команды `code` в `PATH`, если установщик предлагает эту опцию.
5. Завершите установку.
6. Полностью закройте старые окна PowerShell.
7. Откройте новый PowerShell.

Проверка:

```powershell
code --version
```

Открытие текущей папки:

```powershell
code .
```

Точка означает текущую папку.

### 4. Что такое `PATH`

`PATH` — список папок, в которых терминал ищет исполняемую программу по короткому имени.

Когда вы вводите:

```powershell
code
```

PowerShell ищет `code` в папках из `PATH`.

После установки программа может быть уже добавлена в `PATH`, но ранее открытый терминал ещё использует старое окружение. Поэтому сначала перезапустите терминал и только потом диагностируйте проблему.

Не редактируйте системный `PATH` вручную без необходимости.

### 5. Интерфейс VS Code

Основные области:

- Explorer — файлы проекта;
- Editor — содержимое файла;
- Terminal — встроенный PowerShell;
- Problems — ошибки анализаторов;
- Source Control — Git;
- Extensions — дополнения;
- Run and Debug — отладчик.

Полезные сочетания:

```text
Ctrl+Shift+P  Command Palette
Ctrl+P        быстрый поиск файла
Ctrl+`        показать/скрыть терминал
Ctrl+S        сохранить файл
Ctrl+Shift+F  поиск по проекту
F2            переименование символа
F5            запуск отладчика
```

В браузере JavaScript обычно управляет web-страницей и использует browser APIs. Node.js выполняет JavaScript как обычную программу на компьютере или сервере.

React Native тоже использует JavaScript/TypeScript, но работает в mobile runtime. Один язык применяется в разных окружениях с разными доступными APIs.

JSON — текстовый формат данных.

```json

  "name": "dota-match-cli",
  "version": "1.0.0",

}
```

Правила JSON:

```json

  "version": "1.0.0",
  "description": "Учебный анализатор матча Dota 2",
  "private": true,
  "type": "module",
  "scripts": {
    "start": "node src/index.js",
    "test": "node --test"

}
```

#### `name`

Техническое имя пакета. Обычно нижний регистр без пробелов.

#### `version`

Версия проекта. Формат `major.minor.patch`, например `1.2.3`.

#### `private`

```json
"private": true
```

Защищает внутренний проект от случайной публикации в npm registry.

#### `type`

```json
"type": "module"
```

Сообщает Node.js, что `.js`-файлы используют современные ES modules с `import` и `export`.

#### `scripts`

Именованные команды проекта:

```json
"scripts": {
  "start": "node src/index.js",
  "test": "node --test"
}
```

Запуск:

```powershell
npm start
npm test
```

`process.exitCode = 1` сообщает терминалу и CI, что выполнение неуспешно, но позволяет Node корректно завершить текущие операции.

## Глава 5. Модули import/export

### 1. Почему не один большой файл

Один файл быстро становится неудобным:

- трудно найти функцию;
- сложно понять зависимости;
- разные задачи перемешиваются;
- возникают случайные изменения;
- тесты подключают лишний код;
- несколько разработчиков чаще конфликтуют.

Модуль — файл с собственной областью видимости, который явно экспортирует публичные значения и импортирует зависимости.

### 2. Первый export

`src/domain/calculations.js`:

```js
export function calculateKda(kills, deaths, assists) {
  const safeDeaths = deaths === 0 ? 1 : deaths;
  return (kills + assists) / safeDeaths;
}
```

Слово `export` делает функцию доступной другим модулям.

### 3. Первый import

`src/index.js`:

```js
import { calculateKda } from "./domain/calculations.js";

const kda = calculateKda(10, 2, 8);
console.log(kda);
```

### 4. Разбор import

```js
import { calculateKda } from "./domain/calculations.js";
```

- `import` — подключение;
- `{ calculateKda }` — named export;
- `from` — источник;
- `./domain/calculations.js` — относительный module specifier.

Путь считается от файла, содержащего import, а не от терминала.

### 5. Расширение `.js`

В Node.js ES modules пишите расширение явно:

```js
import { calculateKda } from "./domain/calculations.js";
```

Не полагайтесь на browser/bundler-style автоматический поиск расширения.

### 6. Несколько exports

```js
export function calculateKda(...) {
  // ...
}

export function roundToTwoDigits(value) {
  // ...
}

export function formatDuration(totalSeconds) {
  // ...
}
```

Импорт:

```js
import {
  calculateKda,
  formatDuration,
  roundToTwoDigits,
} from "./domain/calculations.js";
```

### 7. Export в конце файла

Альтернативный стиль:

```js
function calculateKda(...) {
  // ...
}

function formatDuration(...) {
  // ...
}

export { calculateKda, formatDuration };
```

Оба варианта корректны. В курсе экспорт пишется рядом с объявлением публичной функции.

### 8. Named и default export

Named export:

```js
export function calculateKda() {}
```

```js
import { calculateKda } from "./calculations.js";
```

Default export:

```js
export default function calculateKda() {}
```

```js
import calculateKda from "./calculations.js";
```

Для domain utilities курс предпочитает named exports:

- имя одинаково в объявлении и import;
- удобно экспортировать несколько функций;
- refactoring безопаснее;
- меньше произвольных переименований.

### 9. Публичное и приватное внутри модуля

```js
function getSafeDeaths(deaths) {
  return deaths === 0 ? 1 : deaths;
}

export function calculateKda(kills, deaths, assists) {
  return (kills + assists) / getSafeDeaths(deaths);
}
```

`getSafeDeaths` не экспортируется. Это внутренняя деталь модуля.

Другой файл не должен зависеть от неё напрямую.

### 10. Модуль данных

`src/data/match.js`:

```js
export const match = {
  id: "8123456789",
  // ...
};
```

`src/index.js`:

```js
import { match } from "./data/match.js";
```

Позже данные перестанут быть hardcoded: вместо этого provider adapter загрузит их по HTTP. Но остальная domain-логика сможет работать с объектом той же формы.

### 11. Направление зависимостей

Желательная схема:

```text
index.js
├── data/match.js
├── domain/match-report.js
└── presentation/print-report.js

domain/match-report.js
├── domain/calculations.js
└── domain/validation.js
```

Domain-функции не импортируют `index.js` и не знают о консоли.

### 12. Circular dependency

Проблема:

```text
a.js импортирует b.js
b.js импортирует a.js
```

Это круговая зависимость. ES modules умеют обрабатывать некоторые циклы, но код становится сложным и может получать ещё не инициализированные значения.

Исправление обычно состоит в выделении общей логики в третий модуль или пересмотре направления зависимостей.

### 13. Ошибка module not found

Проверьте:

- начинается ли локальный путь с `./` или `../`;
- есть ли `.js`;
- совпадает ли регистр имени;
- существует ли файл;
- путь считается от импортирующего файла;
- есть ли `"type": "module"`.

### 14. Импорт built-in модулей Node.js

Встроенный модуль не использует относительный путь:

```js
import { readFile } from "node:fs/promises";
```

Префикс `node:` явно показывает, что это встроенный модуль Node.js, а не npm package.

## Глава 6. npm, pnpm, зависимости и scripts

### 1. Что такое package

Package — опубликованный или локальный модуль с кодом и `package.json`.

Примеры будущих packages:

- клиент PostgreSQL;
- framework NestJS;
- runtime validator Zod;
- test runner Vitest;
- formatter Prettier.

Package manager скачивает packages, проверяет их metadata, строит дерево зависимостей и выполняет scripts.

### 2. npm

npm состоит из:

- online registry с пакетами;
- CLI-команды `npm`;
- форматов `package.json` и `package-lock.json`.

Проверка:

```powershell
npm --version
```

### 3. Установить все зависимости проекта

Если repository уже содержит `package.json` и `package-lock.json`:

```powershell
npm install
```

npm читает описания и создаёт `node_modules`.

Для CI и полностью воспроизводимой установки по lockfile:

```powershell
npm ci
```

`npm ci` требует согласованный lockfile, удаляет существующее дерево установки и не изменяет lockfile. На локальном первом этапе используйте `npm install`; в CI позднее — `npm ci`.

### 4. Установить production dependency

Пример:

```powershell
npm install zod
```

В `package.json` появится:

```json
"dependencies": {
  "zod": "^..."
}
```

Production dependency нужна приложению во время обычной работы.

### 5. Установить devDependency

```powershell
npm install --save-dev prettier
```

Сокращённо:

```powershell
npm install -D prettier
```

В `package.json`:

```json
"devDependencies": {
  "prettier": "..."
}
```

Dev dependency нужна для разработки, тестов, сборки или анализа кода, но не является частью runtime-логики приложения.

### 6. Удалить package

```powershell
npm uninstall zod
```

Не удаляйте package только вручную из `node_modules`: package manager восстановит её при следующей установке.

### 7. Семантические версии

Версия:

```text
3.9.5
```

Части:

```text
major.minor.patch
```

- major — несовместимые изменения;
- minor — новая обратно совместимая функциональность;
- patch — обратно совместимое исправление.

Диапазон:

```json
"some-package": "^3.9.5"
```

`^` обычно разрешает совместимые обновления в рамках major. Точное поведение зависит от начальной версии.

Lockfile сохраняет конкретно разрешённые версии, даже если `package.json` содержит диапазон.

### 8. Прямые и транзитивные зависимости

Вы установили package A. Она использует B и C. Тогда:

- A — прямая dependency вашего проекта;
- B и C — транзитивные dependencies.

Ваш проект зависит от всего дерева. Поэтому даже маленькая установка может добавить много packages.

### 9. Безопасность зависимостей

Перед добавлением package спросите:

1. Нужна ли она вообще?
2. Поддерживается ли она?
3. Совместима ли лицензия?
4. Есть ли security advisories?
5. Насколько велика dependency tree?
6. Можно ли решить задачу встроенным API?

Не устанавливайте пакет только потому, что первое случайное руководство использует его.

Команда:

```powershell
npm audit
```

## Глава 7. Форматирование и статическая проверка

### 1. Три разных проверки

#### Formatter

Меняет внешний вид кода:

- отступы;
- переносы строк;
- пробелы;
- кавычки;
- размещение скобок.

#### Linter

Ищет подозрительные конструкции и нарушения правил:

- неиспользуемые переменные;
- неизвестные имена;
- недостижимый код;
- потенциальные ошибки.

Инструмент: ESLint.

Проверяют поведение программы:

## Глава 8. Отладка Node.js в терминале и VS Code

### 1. Отладка — это поиск факта

Не начинайте со случайного изменения кода. Сначала сформулируйте:

```text
Ожидалось:
Получилось:
Минимальный вход:
Первая функция, где значения расходятся:
```

Цель отладки — найти первую точку, в которой реальное состояние отличается от ожидаемого.

### 2. Воспроизводимый пример

Проблема должна повторяться одной командой:

```powershell
npm start
```

или одним тестом:

```powershell
npm test -- --test-name-pattern="ноль смертей"
```

Если ошибка возникает случайно, запишите входные данные, время, версию Node.js и точную команду.

### 3. Stack trace Node.js

Пример:

```text
TypeError: Cannot read properties of undefined (reading 'kills')
    at analyzePlayer (src/domain/match-report.js:12:21)
    at createMatchReport (src/domain/match-report.js:45:18)
    at src/index.js:7:18
```

Читайте:

1. Тип: `TypeError`.
2. Сообщение: чтение `kills` у `undefined`.
3. Первая строка вашего кода: `match-report.js:12`.
4. Цепочка вызовов ниже.

Откройте строку 12 и выясните, какое значение оказалось `undefined`.

### 4. Временный structured log

```js
console.log({
  function: "analyzePlayer",
  player,
});
```

Объект понятнее нескольких несвязанных значений:

```js
console.log(player, kills, deaths, assists);
```

Используйте метку, чтобы знать источник лога.

После исправления временные логи удалите. В production позднее появится structured logger.

Не выводите:

- API keys;
- access/refresh tokens;
- пароли;
- `.env` целиком;
- персональные данные без необходимости.

### 5. Breakpoint

Breakpoint останавливает программу перед выбранной строкой.

В VS Code:

1. Откройте `.js`-файл.
2. Нажмите слева от номера строки.
3. Появится красная точка.
4. Откройте Run and Debug.
5. Запустите программу.

Во время остановки доступны:

- Variables;
- Watch;
- Call Stack;
- Breakpoints;
- Debug Console.

### 6. Конфигурация запуска

Создайте `.vscode\launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "node",
      "request": "launch",
      "name": "Debug CLI",
      "program": "${workspaceFolder}/src/index.js",
      "skipFiles": ["<node_internals>/**"]
    }
  ]
}
```

Части:

- `type: node` — Node.js debugger;
- `request: launch` — VS Code запускает процесс;
- `program` — entry point;
- `workspaceFolder` — открытый корень проекта;
- `skipFiles` — не заходить в internals Node.js без необходимости.

### 7. Step Over, Into и Out

- Step Over — выполнить текущую строку, не заходя внутрь вызываемой функции.
- Step Into — зайти внутрь функции.
- Step Out — выполнить остаток текущей функции и вернуться к вызывающему коду.
- Continue — продолжить до следующего breakpoint.

Если ошибка в `createMatchReport`, Step Into помогает проследить `validateMatch`, `analyzePlayer` и `createTeamSummary`.

## Глава 9. Первые автоматические тесты

### 1. Зачем нужны тесты

Ручная проверка `console.log` отвечает только на текущий запуск. После изменения формулы нужно снова помнить все случаи и сравнивать вывод.

Автоматический тест:

- задаёт вход;
- запускает функцию;
- сравнивает результат с ожиданием;
- завершается ошибкой при несовпадении;
- повторяется одной командой.

### 2. Встроенный test runner Node.js

Первая версия проекта использует встроенные модули:

```js
import test from "node:test";
import assert from "node:assert/strict";
```

Внешняя dependency пока не нужна.

Script:

```json
"test": "node --test"
```

Запуск:

```powershell
npm test
```

### 3. Первый тест

`test/calculations.test.js`:

```js
import test from "node:test";
import assert from "node:assert/strict";

import { calculateKda } from "../src/domain/calculations.js";

test("calculateKda рассчитывает обычный случай", () => {
  const actual = calculateKda(10, 2, 8);
  const expected = 9;

  assert.equal(actual, expected);
});
```

### 4. Arrange, Act, Assert

Структура теста:

```text
Arrange — подготовить вход и ожидание
Act     — выполнить функцию
Assert  — сравнить результат
```

В маленьком тесте эти части могут занимать по одной строке.

### 5. Имя теста

Плохо:

```js
test("test 1", ...)
```

Хорошо:

```js
test("calculateKda использует единицу как делитель при нуле смертей", ...)
```

При падении имя должно объяснить нарушенное правило.

### 6. Граничный случай

```js
test("calculateKda не возвращает Infinity при нуле смертей", () => {
  const actual = calculateKda(5, 0, 5);

  assert.equal(actual, 10);
  assert.equal(Number.isFinite(actual), true);
});
```

### 7. Сравнение объектов

Для структур используйте deep equality:

```js
assert.deepEqual(actual, expected);
```

`assert.equal` сравнивает ссылки объектов, поэтому два отдельных одинаковых объекта через него не равны.

### 8. Проверка ошибки

```js
assert.throws(
  () => analyzePlayer(invalidPlayer),
  /kills должен быть неотрицательным числом/,
);
```

Тест проверяет и сам факт ошибки, и полезную часть сообщения.

### 9. Проверка неизменности входа

```js
test("analyzePlayer не изменяет исходный объект", () => {
  const player = {
    name: "North",
    hero: "Juggernaut",
    team: "radiant",
    kills: 12,
    deaths: 2,
    assists: 9,
  };

  const originalCopy = { ...player };

  analyzePlayer(player);

  assert.deepEqual(player, originalCopy);
  assert.equal(player.kda, undefined);
});
```

### 10. Test fixture

Fixture — заранее подготовленные данные для теста.

Большой объект можно создавать функцией:

```js
function createValidPlayer(overrides = {}) {
  return {
    name: "North",
    hero: "Juggernaut",
    team: "radiant",
    kills: 12,
    deaths: 2,
    assists: 9,
    ...overrides,
  };
}
```

Тест отрицательных kills:

```js
const player = createValidPlayer({ kills: -1 });
```

Каждый тест получает новый объект и не зависит от изменений другого теста.

### 11. Один тест — одно бизнес-правило

Не собирайте двадцать несвязанных проверок под именем «всё работает». При падении будет непонятно, что сломано.

Допустимо несколько assertions, если они описывают один результат, например полную team summary.

### 12. Детерминированность

Тест должен давать одинаковый результат при одинаковом коде.

Источники нестабильности:

- текущее время;
- случайные числа;
- реальный внешний API;
- порядок общего изменяемого массива;
- timezone;
- сеть.

Unit tests не вызывают OpenDota. Позже provider tests используют сохранённые fixtures и отдельные integration checks.

### 13. Не тестируйте внутреннюю реализацию без необходимости

Тестируйте публичное поведение:

```text
вход → результат/ошибка
```

Если внутренняя функция не экспортируется, обычно не нужно экспортировать её только ради теста. Проверьте результат через публичную функцию.

### 14. Красный, зелёный, улучшение

Полезный цикл:

1. Написать тест, который падает.
2. Убедиться, что он падает по ожидаемой причине.
3. Реализовать минимальное исправление.
4. Увидеть зелёный тест.
5. Улучшить код, сохраняя зелёные тесты.

Тест, который никогда не был замечен падающим, может проверять не то условие.

### 15. Что означает падение

Падение теста не всегда означает ошибку production-кода. Возможны:

- неправильное новое поведение;
- устаревшее ожидание теста;
- ошибка fixture;
- неправильная environment configuration.

Не меняйте expected только ради зелёного статуса. Сначала решите, какое бизнес-правило правильное.

```javascript
export function roundToTwoDigits(value) {
  return Math.round(value * 100) / 100;
}

export function calculateKda(kills, deaths, assists) {
  const safeDeaths = deaths === 0 ? 1 : deaths;
  return (kills + assists) / safeDeaths;
}

export function formatDuration(totalSeconds) {
  const minutes = Math.floor(totalSeconds / 60);
  const seconds = totalSeconds % 60;
  return `${minutes}:${String(seconds).padStart(2, "0")}`;
}
```

### `course/part-02-tooling/examples/dota-match-cli/src/domain/match-report.js`

```javascript
import {
  calculateKda,
  formatDuration,
  roundToTwoDigits,
} from "./calculations.js";
import { validateMatch, validatePlayer } from "./validation.js";

export function analyzePlayer(player) {
  const errors = validatePlayer(player);

  if (errors.length > 0) {
    throw new Error(`Невалидный игрок: ${errors.join(", ")}`);
  }

  return {
    ...player,
    kda: roundToTwoDigits(
      calculateKda(player.kills, player.deaths, player.assists),
    ),
  };
}

export function createTeamSummary(players, team) {
  const teamPlayers = players.filter((player) => player.team === team);

  const kills = teamPlayers.reduce((sum, player) => sum + player.kills, 0);
  const deaths = teamPlayers.reduce((sum, player) => sum + player.deaths, 0);
  const assists = teamPlayers.reduce((sum, player) => sum + player.assists, 0);
  const totalKda = teamPlayers.reduce((sum, player) => {
    const exactKda = calculateKda(
      player.kills,
      player.deaths,
      player.assists,
    );

    return sum + exactKda;
  }, 0);
  const averageKda = teamPlayers.length === 0
    ? 0
    : roundToTwoDigits(totalKda / teamPlayers.length);

  return {
    team,
    playerCount: teamPlayers.length,
    kills,
    deaths,
    assists,
    averageKda,
  };
}

export function findTopPlayer(players) {
  if (players.length === 0) {
    return null;
  }

  let topPlayer = players[0];

  for (const player of players) {
    if (player.kda > topPlayer.kda) {
      topPlayer = player;
    }
  }

  return topPlayer;
}

export function createMatchReport(match) {
  const errors = validateMatch(match);

  if (errors.length > 0) {
    throw new Error(`Невалидный матч: ${errors.join("; ")}`);
  }

  const analyzedPlayers = match.players.map(analyzePlayer);

  return {
    matchId: match.id,
    duration: formatDuration(match.durationSeconds),
    winner: match.radiantWin ? match.radiantTeam : match.direTeam,
    radiant: createTeamSummary(analyzedPlayers, "radiant"),
    dire: createTeamSummary(analyzedPlayers, "dire"),
    topPlayer: findTopPlayer(analyzedPlayers),
    players: analyzedPlayers,
  };
}
```

```javascript
export function isNonEmptyString(value) {
  return typeof value === "string" && value.trim().length > 0;
}

export function isNonNegativeNumber(value) {
  return typeof value === "number"
    && Number.isFinite(value)
    && value >= 0;
}

export function validatePlayer(player) {
  if (typeof player !== "object" || player === null) {
    return ["player должен быть объектом"];
  }

  const errors = [];

  if (!isNonEmptyString(player.name)) {
    errors.push("name должен быть непустой строкой");
  }

  if (!isNonEmptyString(player.hero)) {
    errors.push("hero должен быть непустой строкой");
  }

  if (player.team !== "radiant" && player.team !== "dire") {
    errors.push("team должен быть radiant или dire");
  }

  if (!isNonNegativeNumber(player.kills)) {
    errors.push("kills должен быть неотрицательным числом");
  }

  if (!isNonNegativeNumber(player.deaths)) {
    errors.push("deaths должен быть неотрицательным числом");
  }

  if (!isNonNegativeNumber(player.assists)) {
    errors.push("assists должен быть неотрицательным числом");
  }

  return errors;
}

export function validateMatch(match) {
  if (typeof match !== "object" || match === null) {
    return ["match должен быть объектом"];
  }

  const errors = [];

  if (!isNonEmptyString(match.id)) {
    errors.push("id должен быть непустой строкой");
  }

  if (match.status !== "finished") {
    errors.push("status должен быть finished");
  }

  if (!isNonNegativeNumber(match.durationSeconds)
    || match.durationSeconds === 0) {
    errors.push("durationSeconds должен быть числом больше нуля");
  }

  if (typeof match.radiantWin !== "boolean") {
    errors.push("radiantWin должен быть boolean");
  }

  if (!isNonEmptyString(match.radiantTeam)) {
    errors.push("radiantTeam должен быть непустой строкой");
  }

  if (!isNonEmptyString(match.direTeam)) {
    errors.push("direTeam должен быть непустой строкой");
  }

  if (!Array.isArray(match.players)) {
    errors.push("players должен быть массивом");
    return errors;
  }

  if (match.players.length !== 10) {
    errors.push("players должен содержать десять игроков");
  }

  const radiantCount = match.players.filter(
    (player) => player?.team === "radiant",
  ).length;
  const direCount = match.players.filter(
    (player) => player?.team === "dire",
  ).length;

  if (radiantCount !== 5) {
    errors.push("в матче должно быть пять игроков Radiant");
  }

  if (direCount !== 5) {
    errors.push("в матче должно быть пять игроков Dire");
  }

  match.players.forEach((player, index) => {
    const playerErrors = validatePlayer(player);

    for (const error of playerErrors) {
      errors.push(`players[${index}]: ${error}`);
    }
  });

  return errors;
}
```
