# Часть 13. Соединяем мобильное приложение с backend

В предыдущей части мы собрали интерфейс на React Native и Expo. Теперь заменим временные данные настоящими ответами нашего NestJS API. Итог этой части — мобильное приложение, которое открывает список матчей, мету и детали матча с собственного backend, умеет загружать следующие страницы и нормально переживает медленную или пропавшую сеть.

## Что вы изучите

1. Где проходит граница между mobile и backend.
2. Как настраивать адрес API для локальной разработки, staging и production.
3. Как получать TypeScript-типы из OpenAPI, а не переписывать модели руками.
4. Как сделать единый HTTP-транспорт и понятные ошибки.
5. Как организовать ключи и время жизни кэша TanStack Query.
6. Как реализовать cursor pagination и фильтры.
7. Как выполнять мутации, инвалидировать кэш и не злоупотреблять optimistic update.
8. Что показывать при потере сети, повторном подключении и частичной ошибке.
9. Как проверять совместимость API и наблюдать ошибки без утечки данных.
10. Как провести итоговую интеграционную лабораторную.

## Результат

К концу части данные движутся по настоящей цепочке:

```text
экран Expo
  -> TanStack Query
  -> типизированный API-клиент
  -> HTTPS /v1/...
  -> NestJS
  -> PostgreSQL/Redis
  -> DTO-ответ
  -> кэш Query
  -> интерфейс
```

## Главные правила части

- OpenAPI backend — единственный источник истины о публичном HTTP-контракте.
- В mobile нет ключей Steam, паролей базы и других секретов.
- `localhost` на телефоне — это сам телефон, а не ваш компьютер.
- Серверные данные хранятся в TanStack Query, а не дублируются в Zustand.
- Идентификаторы Dota 2, Steam и матчей передаются строками.
- Сгенерированный код не редактируется вручную.
- Ошибка должна сохранять `status`, машинный `code` и `requestId`, если backend их прислал.
