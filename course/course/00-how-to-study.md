# Как проходить курс

## 1. Для кого этот курс

Курс начинается с абсолютного нуля. От вас не требуется заранее знать:

- что такое переменная;
- чем функция отличается от файла;
- что делают Node.js и React;
- как работает база данных;
- как пользоваться Git;
- что означают HTTP, JSON, API, backend и frontend.

Архитектурная теория будет полезна, но каждое понятие мы повторно свяжем с конкретным кодом.

## 2. Какой результат будет в конце

Вы создадите работающую систему:

```text
Источник данных Dota 2
→ Node.js worker
→ PostgreSQL
→ аналитические расчёты
→ NestJS REST API
→ React Native приложение
```

В учебной production-версии будут:

- профессиональные матчи;
- команды и игроки;
- драфты;
- статистика;
- мета героев;
- поиск;
- избранное;
- push-уведомления;
- тесты;
- staging и production deployment.

Собственный replay-парсер и ClickHouse рассматриваются как продвинутые расширения после основной версии.

## 3. Правильный способ обучения

### Печатайте код самостоятельно

Не вставляйте весь пример целиком. Когда вы набираете код, вы замечаете:

- где стоят скобки;
- зачем нужна запятая;
- где начинается и заканчивается блок;
- как называются переменные;
- какие ошибки появляются из-за опечаток.

### После каждого примера изменяйте его

Если пример считает KDA, измените:

- значения kills/deaths/assists;
- имя игрока;
- формулу;
- формат вывода.

Пример считается понятым, только если вы можете предсказать результат до запуска.

### Ведите журнал ошибок

Создайте файл `learning/error-journal.md`. Для каждой существенной ошибки записывайте:

```text
Дата:
Что я хотел сделать:
Текст ошибки:
Причина:
Как исправил:
Как избежать повторения:
```

Ошибка — это не провал, а конкретная информация о несовпадении ожидания программы и написанного кода.

### Не переходите дальше без контрольной точки

В конце главы есть Definition of Done. Следующая глава предполагает, что предыдущий результат работает.

## 4. Рекомендуемый ритм

Для новичка:

- 5 занятий в неделю;
- 60–120 минут на занятие;
- не больше одной новой крупной темы за занятие;
- отдельный день на повторение и упражнения.

Пример занятия:

1. 15 минут — повторение.
2. 25 минут — теория.
3. 40 минут — код.
4. 20 минут — упражнения.
5. 10 минут — запись выводов и ошибок.

## 5. Как читать примеры кода

Для каждого фрагмента отвечайте на пять вопросов:

1. Какие данные поступают на вход?
2. Где они хранятся?
3. Какая операция над ними выполняется?
4. Что получается на выходе?
5. Что произойдёт при неправильных данных?

Пример:

```js
const kills = 10;
const deaths = 2;
const ratio = kills / deaths;
console.log(ratio);
```

Разбор:

- на входе числа `10` и `2`;
- они хранятся в `kills` и `deaths`;
- выполняется деление;
- результат сохраняется в `ratio`;
- `console.log` выводит `5`;
- при `deaths = 0` понадобится отдельное правило.

## 6. Что значит «я понял тему»

Тема понята, если вы можете:

- объяснить её обычными словами;
- написать маленький пример без копирования;
- изменить пример;
- найти простую ошибку;
- применить тему к данным Dota 2.

Запомнить синтаксис дословно не требуется. Даже опытные разработчики регулярно открывают документацию.

## 7. Как работать с Codex во время курса

Полезные запросы:

```text
Объясни эту ошибку, но не пиши готовое решение.
Дай одну подсказку и дождись моей попытки.
Проверь мой код по критериям главы 3.
Задай мне пять вопросов по функциям.
Покажи, как выполнить этот код по шагам.
Сравни мой результат с Definition of Done.
```

Неполезный для обучения запрос:

```text
Сделай всё приложение целиком, а я просто вставлю код.
```

Готовый код может собрать продукт, но не научит вас исправлять его после первого изменения API или патча Dota 2.

## 8. Правила учебного проекта

- TypeScript strict включается, как только изучены основы JavaScript.
- Все секреты хранятся вне кода.
- Каждая функция имеет понятное имя и одну основную ответственность.
- Большая задача разбивается на маленькие проверяемые шаги.
- Любая внешняя структура данных проверяется до сохранения.
- Любая ошибка либо обработана, либо сознательно передана выше.
- После каждого законченного блока создаётся Git commit.
- Функция считается готовой после теста, а не после первого успешного запуска.

## 9. Папки, которые появятся во время курса

```text
dota-analytics/
  learning/       маленькие учебные упражнения
  apps/           настоящие приложения
  packages/       общий код
  docs/           решения и описания
  infra/          локальная и production-инфраструктура
```

Первые главы работают в `learning`. Настоящий проект начинается только после того, как вы уверенно понимаете переменные, функции, массивы, объекты и асинхронность.

## 10. Главный принцип

Не пытайтесь понять весь будущий проект одновременно. В каждый момент времени вам нужна только следующая работающая ступень.

Первая ступень:

```text
Ввести статистику игрока → рассчитать KDA → вывести результат
```

Позже та же идея вырастет в:

```text
Получить матч из API → проверить данные → сохранить в БД
→ рассчитать статистику → показать в мобильном приложении
```

## 11. Как получить именно выпущенное приложение

После частей 1–17 не уходите сразу в replay, ClickHouse и ML. Сначала пройдите обязательную линию запуска:

```text
часть 21 -> сборка единого MVP
часть 22 -> AWS
часть 23 -> App Store и Google Play
часть 24 -> разрешённая монетизация
-> выпускной проект
```

Части 18–20 остаются продвинутыми расширениями. Они не являются условием первого запуска.

Полный порядок контрольных релизов описан в [маршруте от нуля до запуска](03-zero-to-launch-roadmap.md).

## 12. Финансовая безопасность

AWS, Expo, домены, developer accounts, store purchases и сторонние API могут стоить денег.

Перед каждой платной операцией:

1. прочитайте актуальный официальный pricing;
2. рассчитайте monthly estimate;
3. создайте budget/alerts;
4. укажите owner и дату удаления временного ресурса;
5. после лабораторной проверьте, что ненужный ресурс действительно удалён;
6. не покупайте годовой commitment до устойчивой нагрузки.

Budget alert предупреждает, но не гарантирует автоматическую остановку расходов.

## 13. Юридическая граница

Публичность данных не означает право продавать их, хранить бессрочно или использовать чужие изображения. До коммерческого запуска вы создадите реестр прав на:

- Steam/Valve data;
- provider API responses;
- replay и derived events;
- hero art;
- team logos;
- player photos;
- tournament names/logos;
- используемые open-source packages.

Если право не подтверждено, функция не входит в платный release. Курс объясняет инженерный процесс compliance, но не заменяет юриста/бухгалтера для вашей страны и рынков распространения.

## 14. Доход не гарантируется

Технически работающая подписка ещё не означает, что люди будут платить. Курс научит:

- поговорить с целевой аудиторией;
- проверить проблему и premium value;
- реализовать безопасную оплату;
- измерить activation, retention, conversion, churn и unit economics;
- запустить ограниченный публичный эксперимент.

Решение продолжать, менять продукт или закрыть гипотезу принимается по реальным данным, а не по количеству написанного кода.
