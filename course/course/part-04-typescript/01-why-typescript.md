# 1. Зачем TypeScript, если уже есть JavaScript

## 1. JavaScript разрешает ошибку до запуска

Возьмём функцию:

```js
function calculateKda(kills, deaths, assists) {
  return (kills + assists) / Math.max(1, deaths);
}
```

Вызов выглядит правдоподобно, но содержит ошибку:

```js
calculateKda("7", 2, 14);
```

`kills` оказался строкой. JavaScript попытается выполнить сложение по своим правилам, и проблема обнаружится только во время запуска — иногда уже у пользователя.

TypeScript позволяет описать контракт:

```ts
function calculateKda(
  kills: number,
  deaths: number,
  assists: number,
): number {
  return (kills + assists) / Math.max(1, deaths);
}
```

Теперь неправильный вызов отмечается до запуска:

```ts
calculateKda("7", 2, 14);
//             ^ строка не подходит параметру number
```

## 2. Что обозначает `: number`

В записи:

```ts
const kills: number = 7;
```

- `const` создаёт переменную;
- `kills` — выбранное нами имя;
- `: number` — type annotation;
- `= 7` — обычное присваивание значения.

Type annotation существует для компилятора и редактора. После компиляции получится JavaScript:

```js
const kills = 7;
```

Типы удаляются. Node.js не читает `: number` во время работы скомпилированного приложения.

## 3. TypeScript — не отдельная runtime-платформа

Упрощённая цепочка:

```text
исходник .ts
→ TypeScript compiler проверяет типы
→ исходник .js
→ Node.js выполняет JavaScript
```

Поэтому:

- TypeScript не заменяет Node.js;
- знание JavaScript остаётся обязательным;
- ошибки логики всё равно возможны;
- данные API всё равно нужно проверять во время выполнения;
- тесты всё равно нужны.

## 4. Какие ошибки TypeScript помогает найти

### Неправильный тип аргумента

```ts
formatDuration("2470");
```

### Пропущенное обязательное поле

```ts
const player: Player = {
  accountId: "1001",
  name: "North",
  // hero отсутствует
};
```

### Опечатка в имени свойства

```ts
player.asssists;
//     ^ такого свойства нет
```

### Недопустимое значение union

```ts
const side: TeamSide = "middle";
```

### Возможный `undefined`

```ts
const first = players[0];
console.log(first.name);
// при строгой настройке first может быть undefined
```

## 5. Что TypeScript не доказывает

Такой код компилируется:

```ts
function divide(first: number, second: number): number {
  return first / second;
}

divide(10, 0);
```

Оба аргумента действительно числа. Но бизнес-правило «делитель не должен быть нулём» нужно проверять отдельно.

Другой пример:

```ts
const response = JSON.parse(text);
```

Типы не могут заглянуть в файл, который пользователь изменит завтра. Внешнее значение проверяется runtime-кодом.

## 6. Статическая и динамическая проверка

| Проверка | Когда | Пример |
|---|---|---|
| static type checking | до запуска | функция ожидает `number`, получила `string` |
| runtime validation | во время работы | JSON содержит 9 игроков вместо 10 |
| автоматический тест | при запуске тестов | win rate рассчитан как 66.67% |

Эти механизмы дополняют друг друга.

## 7. Тип как документация и ограничение

```ts
function analyzeMatchHistory(
  matches: readonly Match[],
): HistoryReport
```

Из одной сигнатуры видно:

- функция принимает массив `Match`;
- массив объявлен только для чтения;
- возвращается `HistoryReport`;
- Promise нет, значит сама функция не выполняет асинхронный I/O.

Хороший тип одновременно помогает человеку, редактору и компилятору.

## 8. Type inference

Не каждый тип нужно писать вручную:

```ts
const kills = 7;
```

Компилятор выводит, что `kills` связан с числом. Это type inference.

Пишите annotation там, где она выражает контракт:

- параметры публичной функции;
- возвращаемый domain-объект;
- значение на границе модулей;
- сложный union;
- место, где inference слишком широк или неочевиден.

Не загромождайте очевидное:

```ts
const playerCount: number = 10;
```

Чаще достаточно:

```ts
const playerCount = 10;
```

## Упражнения

1. Добавьте типы в `calculateKda`.
2. Вызовите её со строкой и прочитайте диагностическое сообщение.
3. Исправьте вызов, не используя `as number`.
4. Запишите сигнатуру функции, которая принимает массив матчей только для чтения и возвращает число.
5. Приведите собственный пример ошибки, которую TypeScript не сможет найти без runtime validation.

## Критерий готовности

Вы можете объяснить, почему TypeScript уменьшает количество ошибок, но не делает JSON от внешнего API автоматически безопасным.
